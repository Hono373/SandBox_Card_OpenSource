# 架构主张：自表现流程链

> 用途：面试自述底稿。从自己的话出发，讲得下去，也扛得住追问。
> 关联：`Architecture总结.md`（全局）、`面试高频问题与参考答案.md`（问答）。

---

## 一句话主张（原话）

> 游戏本质是动画的串联。我设计了一套"动画实体"——内建逻辑、支持修正、封装成流程类，本质是一条回放链条：**游戏在逻辑推进中生成回放，再拼接回放。**

## 这个抽象的名字

**自表现命令链（self-presenting command chain）**：命令模式的变体。每个流程节点自带表现，由全局队列定序播放。

业界近亲：Unity Timeline / Playables 的思路，但不用它的 Runtime，因为需要节点内联逻辑。

---

## 三层展开

### 第一层：流程类 = 逻辑与表现的同一居所

`BattleFlow` 是基类。`Init()` 里 `GameAnim.Flow(GetType().Name)` 建一条**暂停的** Sequence，然后交给 `FlowBuild()` 填充。

子类在 `FlowBuild()` 里同时做两件事——推进逻辑、拼接动画：

```csharp
// c:/Work/SandBox_Card/Assets/GameCode/GameManager/GameModify/BattleCardUsePhaseFlow.cs
protected override void FlowBuild()
{
    var ui = ...GetCardUI(card);
    ui.stateEnum = CardStateEnum.Destroy;

    battleCardModify.Start(card, needSettle);          // 逻辑：修正
    ...GetPile(PileEnum.Hand).Remove(card);            // 逻辑：移出手牌

    battleCardUseFlow.Start(card, choice);
    flow.Join(cardDestroyFlow.Start(ui).flow);         // 表现：拼入销毁动画
    flow.Join(battleCardUseFlow.flow);                 // 表现：拼入结算动画
    flow.Join(refreshUnitModifierUIs.Start().flow);

    ...CalculateArg(); ...Arrange();                   // 逻辑：重算排列
    flow.Append(battleEndCheckFlow.Start().flow);      // 表现：收尾
}
```

**收益**：新增一种游戏行为 = 新增一个类。不用去别处注册、不用维护第二份演出表。

### 第二层：修正器接入

流程类的字段是 `[Serializable]` 且被 `[SerializeReference]` 持有 → Modifier 可以作用在流程数据上。

修正管线：一份数据 → 多次修正（`GameModifyCenter.Modify`）→ 一次消费。
`ModifierEffect<T>` 以 `is` 判断路由，命中就改 context。

### 第三层：全局队列定序

`GameAnimFlow` 持有 `Queue<Sequence>` + `current`：

- 入队即 `Pause()`，挂 `onComplete`
- 前一个播完 → `Clear()` → `TryStart()` 下一个
- 每个 flow 带 `intId` + `stringId`，日志可追踪

顺序由单一队列裁决，不会乱序。

## 能力边界（主动说，比被问出来强）

| 能力 | 支持 | 说明 |
|---|---|---|
| 回放 / 观战 | ✅ | 加一层参数记录，重播时重建 flow |
| 跳过战斗 | ✅ | `skipFlow` 整体跳过 |
| 悔棋 | ❌ | 需要逻辑状态快照，动画列表给不了 |
| 无头模拟（跑数值平衡） | ❌ | 流程推进靠动画完成回调，不播回调不来 |

这些不是做不到，是**为局部可读性付的费**：逻辑与演出写在同一处，换来"看一个类就知道这一步干什么、演什么"。卡牌游戏里这笔买卖划算。

## 追问预案

**Q：逻辑和表现到底分没分？**
A：微观分离、宏观交错。单次结算内先算清再演；流程层面是一步一演，用动画完成回调当节拍器。

**Q：为什么不用 async/await 做动画链？**
A：前作 CardQuest 用过，链一断就散、异常吞在 await 里。Sequence 是可检视、可中断、可定序的对象。

**Q：你说这是回放，那能录像吗？**
A：能，但存的是 **flow 参数**不是 Sequence 实例——killed 的 Sequence 无法复活，且存实例只能回放演出、不回放逻辑。重建 flow 时逻辑会一起重放。要闭环还差随机种子化。

**Q：为什么不干脆做成确定性模拟？**
A：用例没有这个需求。这款游戏不需要悔棋和录像，加这层只会让节点变脏。
