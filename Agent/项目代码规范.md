# 项目代码规范

## 1. 禁止容错写法

禁止一切容错写法：任何把错误吞掉、静默降级、以兜底掩盖失败的写法都不允许，错误必须在出错点立即暴露（fail-loud）。包括但不限于：

- 禁止 `?.`（null 条件运算符）静默跳过空引用。
- 禁止 `??` / `??=` 等给可能为 null 的值塞默认值兜底。
- 禁止 try-catch 后吞掉异常、或只打日志继续往下跑。
- 禁止"以防万一"式的判空返回、失败分支返回默认值、静默 return 等兜底逻辑。
- 必须直接访问成员、直接让异常抛出，让 NullReferenceException 等问题在出错点立即暴露。
- **判空（显式 `if (x == null)`）必须由用户明确要求才能写**；用户没要求时，不得自行添加任何判空保护、容错分支或默认值兜底。
- 用户未要求判空、而代码又确实存在空引用风险的：不自行补判空，而是停下来质疑用户，指出该处缺少判空约定、需求不明确，由用户裁决后再动手。
- 依据：用户理论上不会在判空环节提出模糊需求。因此一旦出现"这里到底要不要判空/兜底"的犹豫，即判定为需求本身有问题，质疑用户是正确动作，自行兜底是错误动作。
- 用户明确要求判空时，写显式 `if (x == null)`，在该分支明确处理或报错，不得静默跳过。

## 2. 命令执行：先按设备性能预估耗时，skipped 默认判为命令写错的阻塞

执行任何 PowerShell / bash 命令（扫描、git、编译、脚本等）都适用：

- 执行前先根据当前设备性能预估耗时，并告知用户，由用户决定是否等待；不允许发出耗时不可预期的命令。
- 默认使用轻量实现，不使用复合命令：不堆管道、不多命令串联、不调 WMI/CIM 类慢路径；查询系统状态用纯 .NET P/Invoke（`GetTickCount` + `GlobalMemoryStatusEx`），查文件用指定编码 + `FileShare::ReadWrite` 的受控读写；需要多步时拆成多条独立命令分别执行。
- 用户 skipped 时的意图是"已超过预期时间"，默认判定为**命令写法错误导致的阻塞**（走了 WMI/CIM、网络、内核 API、大 IO 等慢或假死路径），**不是**用户不想等。CPU 不是瓶颈，不存在需要数分钟的正常命令。
- 出现 skipped 立即停止重试同一条命令，拆解为更轻量的单条命令，避免 `Get-CimInstance` / `wmic` / `Get-WmiObject` / `systeminfo` / 远程网络调用；必要时交用户本地终端执行。
- 可能卡住的命令主动内嵌计时器（PowerShell `Start-Job` + `Wait-Job -Timeout`，查询类 60 秒、构建/编译/重启类 120 秒），超时 `Stop-Job` 并降级，不依赖用户手动跳过。

## 3. 代码检索范围限定在 `Assets/GameCode`

所有代码检索、扫描、统计、写法排查、引用/定义查找，默认只在 `c:/Work/SandBox_Card/Assets/GameCode` 内进行：

- 项目自有代码的口径 = `Assets/GameCode`。报"项目中存在 / 不存在某写法"时，主体结论以此为准。
- 不把 `Assets/DataBase`（配置数据脚本）、`Assets/Plugins`（第三方插件，如 `luban_unity-main`）、`Packages`、`Library` 等目录的命中混入项目代码结论。
- 其他目录确有命中时，可单独附注"另有 N 处在 X 目录"，但不列入需要处理的项目代码清单。
- 需要扩大范围（跨目录全局检索）时，先说明原因并取得用户明确同意再执行。

## 4. 文件位置书写格式：反引号内纯完整路径（IDE 只认这一种可点击跳转）

给用户报文件位置（bug 定位、改动点、调用点）时必须写成可点击跳转的形式：

- 唯一有效写法：反引号内放完整绝对路径、以真实扩展名结尾、中间不夹任何文字，例如 `c:/Work/SandBox_Card/Assets/GameCode/GameManager/GameModify/BattleCardUsePhase.cs`。
- 行号、说明括号、注释一律写在反引号**外面**：`c:/Work/SandBox_Card/Assets/GameCode/GameManager/GameModify/BattleCardUsePhase.cs`（第 30 行）、`c:/Work/SandBox_Card/Assets/GameCode/GameManager/GameModify/SkillApplyPhase.cs` 第 46-60 行。
- 实测：把"第 X 行"写进反引号内（`路径 第 10 行`）会导致整段失效、点不动；只有"反引号 + 纯路径 + 反引号"才可点击。
- 禁止用 `.../` 省略号缩写路径，必须从 `c:/Work/SandBox_Card/` 写全，否则 IDE 不识别为文件引用。
- 禁止改用 markdown 超链接、`file://` 协议、`vscode://` 协议——本项目 IDE 中点击均无法跳转。
- 同一文件有多个位置时：路径只写一次，后面并列多个行号，例如 `c:/Work/SandBox_Card/Assets/GameCode/GameManager/GameBattle/DeckBuildBattle/Prefab/BattleCard/BattleCardPremodify_OnChoice.cs` 第 11 行、第 25 行。
