# 卡表数据链路（Excel → Luban → Json → 游戏）

> 最后更新：2026-10-12

## 一句话

卡牌配置以 **`Assets/GameDataBase/DB.xlsx` 为唯一权威源**，经 Luban 导出为
`Assets/GameDataBase/CardInfo.json`（JSON 数组），游戏用 `GameDB.LoadInfo<CardInfo>()`
直接反序列化成 `CardInfo` 实例。**jsonl 已退役，json 不再手工维护。**

关键设计：`CardInfo.json` 的字段名 / 类型名 / 多态位置与游戏侧
`Assets/GameCode/GameManager/GameSerialize/CardInfo/` 下的类**完全一致**，因此
Newtonsoft 可以零映射直接反序列化，不需要任何手工翻译层。

## 数据流

```
DB.xlsx（sheet "Card"）                  ← 唯一权威源，人工编辑
   │
   │  ExcelToJson/CreateJsonCN.bat
   │    · cd /d 到 ExcelToJson（工作目录必须在此，见下）
   │    · 调用 Tools/Luban/Luban.dll（已打过补丁）
   │    · 输出到临时目录 _out_tmp，回拷产物后删除
   ▼
Assets/GameDataBase/CardInfo.json          ← 产物，JSON 数组
   │                                         旧文件自动备份为 CardInfo.json.old
   ▼
GameDB.LoadInfo<CardInfo>()               ← 运行时
   · 首字符是 '['  → JArray 解析（Luban 格式）
   · 否则          → 逐行解析（旧 jsonl 格式，保留兼容）
   · $type 由 ShortTypeNameBinder 解析，短名 "CostValue" 与
     完整名 "CostValue, Assembly-CSharp" 两种写法都接受
   ▼
Dictionary<string, CardInfo>
```

## 工作流

### 方式一：批量编辑（新增卡、成批改数值）

1. 打开 `Assets/GameDataBase/DB.xlsx`，在 `Card` sheet 编辑
   - **第 1~6 行是表头，不要动**；数据从第 7 行开始
   - 六个 `$type` 列（D/F/K/R/T/V）已配下拉，直接选
2. 保存并**关闭 Excel**（导出时文件被占用会失败）
3. 双击运行 `ExcelToJson/CreateJsonCN.bat`
4. 回到 Unity 等资源刷新

### 方式二：单卡精修（用 Odin 的多态提示）

1. 选中 `Assets/GameDataBase/CardInfoCreator.asset`
2. 点 **「刷新清单缓存」**（若 DB.xlsx 比 json 新会弹警告，需先跑 bat）
3. 在 `key` 下拉选一张卡（下拉显示为 `key - 中文名`），点 **「获取info数据」**
4. 在 `info` 字段上编辑 —— Odin 的多态类型下拉、`[ValueDropdown]`、`[MinValue]` 全部生效
5. 点 **「写入info并同步表格」** → 一步完成：写回 `DB.xlsx`（自动备份 `.bak`、自动重套数据验证）→ **直接调用 Luban 重新导出**（不经 bat，产物先出临时目录再回拷）→ 重载面板。**内存 / Excel / json 三处一致。**

> **权威性**：两种方式写同一份数据，**以 Excel 为准**。
> Odin 里的修改必须经「同步回表格」落回 Excel，否则下次跑 bat 会被覆盖。

## 表头结构（Card sheet）

| 行 | 内容 |
|---|---|
| 1 | `##var` — 顶层字段名 |
| 2 | `##type` — 顶层类型名 |
| 3 | `##var` — 第一层子字段名（`cost.*` / `interactive.$type` / `choiceRule.*` / `timings.*`） |
| 4 | `##var` — 第二层（`timings[].skills.*` 等） |
| 5 | `##var` — 第三层（`skills[].rangeRule.*` / `countRule.$type` / `effect.$type`） |
| 6 | `##var` — 第四层（`rangeRule.conditions.*` / `effectAnimData.*`） |
| 7+ | 数据 |

- 字段名以 `*` 开头 = Luban 的 `multi_rows` 标记，**凡 `list` 类型字段都必须加**
  - 已加的：`*timings`(M1)、`*skills`(O3)、`choiceRule.conditions`(K3)、`rangeRule.conditions`(Q5)
  - **不加的后果**：Luban 无法解析该 list 的子字段，导出报
    `error.data.parse_failed` / `单元格:[Sxx] xxx 缺少数据`
  - 这个错只在 list **首次有数据**时暴露（`conditions` 一直为空时看不出来）
- 父字段的列跨度靠**合并单元格**表达；子列名必须逐列写出，只给合并跨度不够

## 多行语义（重要）

一张卡**可以占多行**：

- `*timings`/`*skills`/`*conditions` 都是列表：**第 i 行承载每个列表的第 i 个元素**；某列表在该行没有元素时它的列留空（=不推进）
- 一个 skill 的 `rangeRule.conditions` 有 N 个就占 N 行；`choiceRule.conditions` 的第 i 个条件落在**整卡第 i 行**（行不够时在末尾补行）
- **卡级字段**（`cardName`/`cost`/`interactive`/`graphic`/`choiceRule.range`）只写在**第一行**
- `timingEnum`/`pileEnum` 写在**每个 timing 的第一行**
- 无 timing 时按 1 行起算，条件多则补行
- Luban 的判断依据：某个字段组的列范围**全空 = 延续上一记录**，非空 = 新记录

写回脚本 (`ExcelToJson/sync_to_excel.py`) 按同样规则展开，行数变化时自动插入/删除行
（从下往上处理，避免行号偏移），并在写值前**清空块内数据列**，避免"原来有 effect、现在没有"时残留旧值。

## 牌组配置（GameInfo）

`Assets/GameRes/Info/GameInfo.asset` 保存玩家牌组：`cardDeckInitial`（每项 = 卡 key + 数量）。

- **只存 key**（字符串），中文名由卡表实时提供 —— 下拉显示为 `[key]中文名`
- 卡牌清单**不再缓存于 asset**：运行时真源是 `GameDB.cardInfos`，编辑器下拉取自 `CardInfoCreator.GetKeyOptions()`
- 点列表的 **「+」** 按钮（`AddCardInitial`）追加一条空条目，再在下拉里选卡、填数量

> 历史沿革：早期用 `CardInitial.keyDescPair`（`KeyDescPair` 结构体）同时存 key 和中文名，
> 导致 ① 中文名冗余进 asset、② `CardInitial` 与 `GameInfo` 互相引用造成循环序列化。
> 现已简化为只存 key。`KeyDescPair` 本身保留，仍被 `InfoExtension.GetDropdownList` 与
> `ModifierAdd` 使用（那套走 ScriptableObject 资产列表，与卡表的 json 模式不同）。

## 注意事项

1. **不要给 bat 加 `-c`**。Luban 生成的代码在 `ProjectLumiyaDB` 命名空间下，与游戏的全局
   数据类**不同套**；加 `-c` 会覆盖 `Assets/DataBase/Script/`，破坏其中 6 处
   `ProjectLumiyaDB` 引用，且生成类游戏用不上。
2. **不要再点 `InfoCreator` 的「写入info数据」维护正式数据**。它只用于临时查看/试改，
   正式数据一律走 Excel。
3. **改表头要同步改四处**：`Defines/CardModel.xml`（字段/多态子类）、`DB.xlsx`（列）、
   `CardInfoRowMapper.cs`（列号映射）、`sync_to_excel.py`（`VALIDATIONS` 下拉）。
   **C# 里新增 `[SerializeReference]` 字段或多态子类时，这四处必须一起加**：否则该字段在卡表里
   没有列，同步回表格时会被当作空值清掉、运行时永远是默认值（`Shield`/`Heal.value` 就踩过这个坑）。
4. **Luban 会删除输出目录中非本次产出的文件**，所以 bat 必须先输出到临时目录再回拷，
   不要直接输出到 `Assets/GameDataBase`。
5. **工作目录**：`dataDir` 相对 conf 文件解析，但 Luban 的 `File.Exists` 按 CWD 查找，
   因此 bat 里用 `cd /d "%~dp0"`（不能用 `pushd` 切到 dataDir）。
6. 当前只有 CardDB 启用；其余 10 张表（Base/Area/Unit/Task/Level/Battle/Story/Archive/UI/Buff）
   在 `Defines/Table.xml` 里注释着，需用时先在 DB.xlsx 建对应 sheet 再取消注释。
7. `CardModel.xml` 的多态子类必须与 C# 侧保持一致。此前漏定义过 `CostNo` / `Heal` / `Shield` / `VariableCount`，一旦数据用到就报 `type:'XXX' 不是合法类型`（已补齐）。新增多态子类时两边都要加，并同步 `sync_to_excel.py` 的 `VALIDATIONS` 下拉。

**关键结论 / 踩坑（避免重复试错）**

- **Luban 多行表规则**：第 i 行承载每个列表的第 i 个元素；某列表在该行没有元素时其列留空（=不推进）。
  **列表多元素不需要新增列**，只靠多行表达。
- **Luban 子列按分组内顺序解析**：新字段必须插在所属分组的**起始顺序内**；放到分组末尾（合并区之外）
  会报 `bean:'X' 缺失列:'Y'`。
- `sync_to_excel.py` 原先逐格 `Cells.Value=` 且未关刷新/自动重算 → 写 663 个单元格要 ~19s，
  是「点按钮编辑器假死」的主因；现已改为**整段批量 `Range.Value`**（读 B 列同样批量）。
- Excel COM `Quit()` **不保证进程退出**，残留进程会占住 `DB.xlsx`（导致下次同步打不开）→ 脚本已按
  PID 兜底 `taskkill`。
- 用 `DispatchEx` 起**独立** Excel 实例，避免 attach 到用户已打开的 Excel。
- `Calculation` 必须在工作簿打开**之后**才能设置。

**验证方式（可复用）**：把 `Defines/*.xml` 与一份 DB.xlsx 副本放进临时目录，用临时 `luban.conf`
（`dataDir="."`）单独跑 Luban，就能在**不碰正式表**的前提下做结构实验。

**待办（backlog）**：把同步契约从「列号」改为「字段路径」——C# 只发路径（如 `graphic.color`），
`sync_to_excel.py` 读表头自动解析「路径 → 列号」。这样插列/挪列/加字段时 C# 零改动，
后续新表（UnitInfo / Modifier 等）也能复用 Python 侧。**未实施，待决**。
